The Subdomain Trick Is the Most Deceptive
paypal.com.login-verify.net/secure — the human eye sees "paypal.com" first and stops reading. But the actual domain (the part immediately before the first single slash) is login-verify.net. PayPal.com is just a subdomain of the attacker's site.

🛡️ Phase 3 — Defending Against Pharming & Homograph Attacks

  • Identify the actual domain: read the URL right-to-left from the first single slash. The part just before / is the real domain.
  • Bookmark important sites and access them only via bookmarks — never by clicking links.
  • Use a browser that shows Punycode for IDN domains (Chrome shows xn-- prefix for suspicious homograph domains).
  • Enable DNSSEC validation on your network to prevent DNS poisoning (pharming via DNS).
  • Use a trusted DNS resolver (Cloudflare's 1.1.1.1, Google's 8.8.8.8) with built-in malware filtering.
  • Check domain registration date with WHOIS — phishing domains are typically days or weeks old.
  • Use browser extensions like uBlock Origin or Netcraft to flag known phishing domains automatically.

How to Read a URL Correctly

URL Anatomy
https://paypal.com.evil.xyz/account/login

scheme : https://
subdomain: paypal.com ← looks real but it's a subdomain!
domain : evil.xyz ← THIS is the actual domain
path : /account/login

▶ Rule: Find the last dot before the first slash. Everything before it is the real domain.
